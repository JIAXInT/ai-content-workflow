事情是这样的。

昨天刷到一条消息，MiniMax 发布了他们的新模型 M3。

本来没太在意，最近大模型发布太多了，麻了。但定睛一看数据，我愣住了。

**SWE-Bench Pro 得分 59.0%，超过 GPT-5.5 和 Gemini 3.1 Pro，接近 Opus 4.7。**

等等。

MiniMax？那个做视频生成的 MiniMax？他们家的文本模型什么时候这么猛了？

我反复确认了两遍，没看错。而且这玩意是开源的。

不是，哥们。

一个开源模型，在编程能力上逼近目前公认的最强闭源模型 Claude Opus 4.7，这事儿是不是有点离谱了？

## 先说说 SWE-Bench Pro 这个基准是干嘛的

它不是那种简单的代码生成测试，让你写个排序算法就完事了。它是给你一个真实的 GitHub 仓库，一个真实的 issue，然后让你去理解整个代码库的结构，定位问题，修复 bug，写测试，提交 PR。

整个过程涉及**代码理解、推理、多文件编辑、测试编写**，是对一个模型「软件工程能力」的综合考验。

M3 在这个基准上拿了 59.0%。

作为对比，Opus 4.7 是目前公认的编程最强模型，GPT-5.5 和 Gemini 3.1 Pro 也是第一梯队。M3 一个开源模型，直接杀进这个圈子，你敢信？

说到这个，我想起去年的一个段子。

当时有人说，开源模型和闭源模型的差距，就像业余选手和职业选手的差距，永远追不上。

结果呢？

DeepSeek 出来的时候，大家觉得差距在缩小。Llama 3 出来的时候，大家觉得「诶，好像能打了」。现在 M3 出来了，直接在编程这个赛道上跟闭源最强掰手腕了。

**不是追不上，是时候未到。**

## 不是单项很强，是全面开花

说真的，M3 最让我惊讶的不是单项能力，而是它在多个维度上的表现。

| 基准测试 | M3 得分 | 说明 |
|---------|--------|------|
| SWE-Bench Pro | 59.0% | 编程能力，接近 Opus 4.7 |
| Terminal-Bench 2.1 | 66.0% | 命令行操作能力 |
| MCP Atlas | 74.2% | 工具理解和使用能力 |
| OmniDocBench | > Gemini 3.1 Pro | 文档理解能力 |
| SVG-Bench | > Opus 4.7 | 矢量图生成能力 |
| Claw-Eval | 最高分 | 自主智能体端到端评估 |

你看到了吗？

不是某一项很强，是几乎每一项都在第一梯队。

这种全面性，说实话，让我有点懵。

## MSA 架构：100 万 token 上下文的秘密

回到 M3 本身，它有几个技术亮点我觉得值得聊聊。

第一个是 MSA，全称 MiniMax Sparse Attention。

这个东西说起来有点技术，但我尽量讲人话。

你知道大模型处理长文本的时候，最大的瓶颈是什么吗？是注意力机制的计算量。传统的注意力机制，计算量会随着文本长度的平方增长。也就是说，文本翻倍，计算量翻四倍。

100 万 token 的上下文窗口，如果用传统方法，计算量会大到根本跑不动。

MSA 的解决方案是稀疏注意力。它不是让模型「看」每一个 token 对其他所有 token 的关系，而是只看最相关的那些。

这听起来好像很简单，但实际做起来很难。难点在于，怎么确定哪些是「最相关的」？如果选错了，模型就会漏掉重要信息，输出质量会大幅下降。

MiniMax 的做法是用一种叫「KV outer gather Q」的操作方式，以 KV 块为外层循环，聚合命中的查询向量。每个块只读取一次，内存访问连续。

**结果就是：**

| 指标 | 提升幅度 |
|------|---------|
| 每 token 计算量 | 降至前代的 1/20 |
| 预填充速度 | 提升 9 倍以上 |
| 解码速度 | 提升 15 倍以上 |

更离谱的是，MiniMax 说 MSA 在大多数能力上和全注意力持平。

也就是说，它又快又准。

100 万 token 的上下文窗口，你想想这会怎样。

你可以把一整本技术文档扔给它，让它从头到尾理解。你可以把一个大型代码仓库的所有文件都塞进去，让它理解整个项目的架构。你可以把一整天的会议录音转成文字，让它帮你总结。

以前这些都是要拆成很多段分别处理的，现在一次性搞定。

## 两个让人「卧槽」的案例

说到这个，我想起一个更有意思的事情。

MiniMax 在论文里提到，他们让 M3 去复现一篇 ICLR 2025 的杰出论文。

你没听错，不是让人类去复现，是让 AI 自己去读论文、理解论文、写代码、跑实验、画图、验证结果。

M3 自主运行了将近 12 小时，产出了 18 次提交和 23 张实验图，成功复现了论文的核心实验。

这整个过程需要多模态理解论文中的曲线和公式，需要长上下文来容纳论文、代码和日志，需要强编码能力来完成长时间线程的复现。

**三个能力缺一不可。**

还有一个更猛的案例。

MiniMax 让 M3 去优化一个 CUDA kernel。

CUDA kernel 是什么？简单说，就是让 GPU 跑得更快的底层代码。这玩意优化起来极其复杂，连很多资深工程师都搞不定。

**M3 的优化过程：**

| 指标 | 数据 |
|------|------|
| 起点 | 无法运行的 Triton 骨架 |
| 耗时 | 约 24 小时 |
| 基准提交 | 147 次 |
| 工具调用 | 1,959 次 |
| 性能提升 | 9.4 倍 |
| FP8 利用率 | 7.6% → 71.3% |

最骚的是，最佳方案出现在第 145 次提交。

也就是说，在经历了多次性能平台期之后，M3 还在持续探索不同的优化方向，没有放弃，最终找到了更好的方案。

这种「不放弃」的精神，说实话，比很多人类工程师都强。

## 数据可信度分析

说到这里，我得坦诚一下。

我还没有亲自测试过 M3。

上面这些数据和案例，都来自 MiniMax 的官方博客。我知道大家可能会说，官方数据肯定有水分，这我理解。

但有几点让我觉得这个发布比较可信：

**第一，基准公开透明。** SWE-Bench Pro 是公认的基准，不是 MiniMax 自己搞的。而且这个基准的测试集是公开的，如果数据造假，很快就会被社区发现。

**第二，承诺全面开源。** MiniMax 说 M3 的技术报告和模型权重会在 10 天内开源。开源意味着所有人都可以验证，如果性能注水，社区会第一时间打脸。

**第三，技术栈完全透明。** MiniMax Code 这个产品是基于 OpenCode 和 Pi 这两个开源项目构建的，代码本身也会开源。这意味着整个技术栈都是透明的。

所以，虽然我没有亲自测试，但我觉得这个发布大概率是靠谱的。

## Token Plan 定价：便宜到离谱

回到 M3 本身，还有一个点我觉得值得聊聊。

它的定价。

MiniMax 推出了一个叫 Token Plan 的订阅服务：

| 档位 | 价格 | 月 Token 额度 |
|------|------|--------------|
| Plus | $20/月 | 约 17 亿 tokens |
| Max | $50/月 | 约 51 亿 tokens |
| Ultra | $120/月 | 约 98 亿 tokens |

文字、图像、语音、音乐共享同一额度池。

你没看错，98 亿 tokens，120 美元。

算一下，**每百万 tokens 大约 0.12 美元**。

这个价格，说实话，有点离谱。

作为对比：

| 模型 | 价格（每百万 tokens） |
|------|---------------------|
| Claude Opus 4 | $15（输入）/ $75（输出） |
| GPT-5.5 | $15（输入）/ $60（输出） |
| MiMo M3 | $0.12 |

**M3 的价格只有 Opus 的百分之一。**

你想想这意味着什么。

以前用最强模型跑一个复杂任务，可能要花几十美元。现在用 M3，可能只要几毛钱。

AI 正在变得越来越便宜，便宜到你不需要纠结「这个任务值不值得用最好的模型」，直接用就行了。

说到这个，我想起前几天跟一个朋友聊天。

他在一家创业公司做 AI 应用，跟我说，现在最大的痛点不是模型不够强，而是太贵了。

「我知道 Opus 4 很猛，但我一个请求要花几美元，我一天跑几千个请求，根本用不起。」

现在 M3 出来了，性能接近 Opus，价格只有百分之一。

你说他会怎么选？

## 开源 vs 闭源：效率 vs 控制

我有时候觉得，AI 行业正在经历一个很有意思的阶段。

去年大家还在讨论「开源模型能不能追上闭源模型」。今年这个问题已经有了答案：**能，而且追得很快。**

M3 不是第一个逼近闭源最强的开源模型，但它是第一个在编程这个核心赛道上做到这一点的。

编程能力，一直是闭源模型的护城河。

因为编程需要的不仅仅是「理解代码」，还需要：
- 理解整个项目的架构
- 理解人类的意图
- 在复杂的代码库中定位问题
- 写出符合规范的代码
- 编写测试来验证修改

这些能力综合起来，就是所谓的「软件工程能力」。

M3 在 SWE-Bench Pro 上的 59.0% 得分，证明开源模型已经具备了这种能力。

坦率的讲，我觉得这对整个行业来说都是好事。

闭源模型再强，你也只能通过 API 来用。API 的价格、速率限制、隐私问题，都是制约因素。

开源模型不一样。你可以本地部署，可以 fine-tune，可以完全控制数据流向。对于很多企业来说，这是刚需。

M3 的出现，让这些企业有了一个真正可用的选择。

**不是「勉强能用」，而是「接近最强」。**

## M3 的短板

当然，M3 也不是没有缺点。

MiniMax 的 PostTrainBench 得分是 0.37，低于 Opus 4.7 的 0.42 和 GPT-5.5 的 0.39。这个基准测试的是模型「训练其他模型」的能力，说明在某些复杂推理场景下，M3 还有差距。

但这个差距已经很小了。而且 M3 是开源的，社区可以继续优化和改进。

说到社区，我想起一件事。

MiniMax 说 MiniMax Code 是基于 OpenCode 和 Pi 这两个开源项目构建的，并且计划未来开源。

这是什么概念？

**整个技术栈都是透明的。** 从底层的注意力机制，到中间的训练框架，到上层的应用工具，全部开源。

这种程度的开放，在大模型领域是很少见的。

大多数公司，即使开源了模型权重，也会把训练数据、训练方法、应用层工具藏起来。MiniMax 选择全部开放，这种态度我觉得值得尊重。

## 思维模式：一个贴心的设计

说回到 M3 本身，它还有一个我觉得很有意思的特性。

它支持「思维模式」的开关。

开启思维模式，模型会花更多时间来推理，适合复杂的任务。关闭思维模式，模型会直接给出答案，适合低延迟的场景。

而且两个模式的价格相同。

这个设计挺贴心的。

很多时候，你并不需要模型「深思熟虑」。比如简单的问答、翻译、摘要，你希望它快点给你答案。但遇到复杂的编程任务、数学推理、多步规划，你希望它认真想想。

**一个模型，两种用法，价格一样。**

这种灵活性，我觉得会成为未来的标配。

## 开源的力量

说真的，我有时候觉得，开源和闭源的竞争，其实就是在比「效率」和「控制」。

闭源模型追求的是「控制」。通过控制模型、控制 API、控制生态，来获取最大的商业价值。

开源模型追求的是「效率」。通过开放、共享、协作，来加速技术的进步和普及。

两条路都有道理，没有绝对的对错。

但从历史来看，「效率」最终往往会战胜「控制」。

- Linux 战胜了 Windows 的服务器市场
- Android 战胜了 iOS 的市场份额
- Kubernetes 战胜了所有商业编排系统

**开源的力量，不在于单个产品的性能，而在于整个生态的活力。**

M3 的出现，让开源生态在编程能力这个关键维度上，第一次真正逼近了闭源最强。

这可能是一个转折点。

## 你能用 M3 做什么？

说到未来，我想起一句话。

「预测未来的最好方式，就是创造它。」

M3 的出现，让开源社区有了一个更强的工具来创造未来。

你想想，一个接近 Opus 4.7 性能的开源模型，价格只有百分之一，支持 100 万 token 的上下文，原生支持多模态。

你可以用它来做什么？

**应用场景：**

| 场景 | 说明 |
|------|------|
| 编程助手 | 帮开发者理解整个代码库，自动定位和修复 bug |
| 智能客服 | 理解超长的对话历史，记住用户的所有偏好 |
| 研究助手 | 阅读和理解整篇论文，甚至复现实验 |

而且这些都是以前只有大公司才能做的事情，现在任何人都可以做。

**这就是开源的力量。**

## 写在最后

说真的，我有时候觉得，我们正处在一个很特殊的历史节点。

AI 的能力在飞速提升，但成本在急剧下降。

M3 是这个趋势的一个最新例证。

**这事儿，我觉得值得记住。**

说到底，技术的进步最终会让所有人受益。

闭源模型再强，你也要付费才能用。开源模型强了，所有人都可以用。

竞争会让价格下降，会让能力提升，会让更多的创新成为可能。

M3 的出现，加速了这个进程。

**这是好事。**
