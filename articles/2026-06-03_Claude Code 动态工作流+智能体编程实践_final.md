# Claude Code 更新了两个炸裂功能，我看完沉默了

[封面图占位符]

事情是这样的。

昨天晚上我照例刷 AI 圈的动态，突然看到 Claude Code 官方连发两篇博客。

一篇讲的是「动态工作流」，另一篇讲的是「智能体编程如何重塑工程组织」。

我当时就想，不就是更新功能嘛，能有多炸？

然后我就点进去了。

说实话，看完之后我沉默了挺久的。

## 先说第一个功能，动态工作流

这个功能简单说就是，Claude Code 现在可以在运行的时候，自己创建和协调多个 AI 智能体来处理复杂任务。

你没看错，不是你去配置它用哪个智能体，而是它自己根据任务需要，即兴创建多个子代理，让它们分工协作。

我给你打个比方。

以前用 Claude Code，就像你只有一个实习生。不管什么任务，都得这一个实习生从头干到尾。写代码是他，查资料是他，测试也是他。

现在不一样了。

现在 Claude Code 变成了一个小团队的 leader。它会根据任务类型，自己决定要拉几个人来干活。需要写代码的拉一个，需要查资料的拉一个，需要测试的再拉一个。然后它自己协调这几个人的工作进度。

我举个具体的例子。

比如你让 Claude Code 帮你做一个安全审计。以前它可能就是读代码、找漏洞、写报告，一个人干。现在它会自己创建一个「研究智能体」去分析代码结构，再创建一个「测试智能体」去跑各种测试，最后自己汇总成报告。

更骚的是，每个智能体都有自己独立的上下文窗口。

这个很关键。

你知道 AI 智能体最怕什么吗？就是上下文太长。一个任务如果执行太久，上下文窗口塞满了，AI 就会开始「智能惰性」——就是它懒得深入思考了，开始给你糊弄。

现在每个子代理都有自己独立的上下文，就不会出现这个问题。研究智能体专注于研究，测试智能体专注于测试，各自干各自的，效率拉满。

我看到这个功能的时候，第一反应是，这不就是 Anthropic 在偷偷搞「智能体操作系统」吗？

## 然后是第二个功能，这个更炸

第二篇博客讲的是 Claude Code 团队自己是怎么用智能体编程的。

坦率的讲，就是 Anthropic 自己的工程师，已经把 Claude Code 当成默认的编程方式了。

他们分享了几个核心变化。

**第一个变化，规划模式变了。**

以前写代码，都是先规划好，详细设计文档写好，然后再动手。

现在不这样了。

现在是「即时规划」（JIT）。就是大概想一下方向，然后直接让 Claude Code 去干。干的过程中遇到问题再调整。

他们说，现在的规划更像是「快速原型」，而不是「详细设计」。

我理解这个转变。

你知道以前那种详细规划的问题在哪吗？就是你规划得再好，实际执行的时候总会遇到各种意外。与其花时间规划一个完美的方案，不如先跑起来再说。

**第二个变化，上下文收集方式变了。**

以前要了解一个项目，得自己去读代码、看文档、问同事。

现在他们的第一反应是，先问 Claude。

他们原话是这么写的：「上下文收集从你自己阅读和推理，变成了先问 Claude。」

这个我太有感触了。

我自己用 Claude Code 也是这样。遇到一个不熟悉的代码库，以前得花好几天才能搞明白架构。现在直接丢给 Claude，让它帮我分析，几分钟就出来了。

**第三个变化，代码审查的方式变了。**

这个是我觉得最骚的。

现在代码审查，Claude 负责处理风格问题、跑测试、检查基本规范。人只专注于那些需要专业判断的东西，比如法律合规、安全策略、架构决策。

也就是说，Claude 把那些「机械性」的审查工作全包了，人只需要做「创造性」的判断。

这就像你请了个私人助理，他帮你把所有邮件都分好类了，你只需要处理那些真正重要的。

**第四个变化，工程瓶颈转移了。**

以前最大的瓶颈是「写代码」。程序员每天大部分时间都在敲代码。

现在最大的瓶颈变成了「验证、审查和安全维护」。

就是说，代码写得快了，但是怎么保证写得对？怎么保证安全？怎么保证符合规范？这些变成了新的瓶颈。

我觉得这个洞察挺深刻的。

## 我看完之后在想什么

说实话，看完这两篇博客，我脑子里第一个冒出来的词是，加速。

Anthropic 不是在做一个编程工具，他们是在重新定义「编程」这件事本身。

你想想看。

以前编程是什么？是一个人在电脑前敲代码。

后来有了 AI 辅助编程，变成了一个人 + AI 写代码。

现在 Claude Code 的方向是什么？是一个 AI 团队在写代码，人只需要做决策。

这个变化太快了。

快到很多程序员还没反应过来，就已经被甩在后面了。

我自己也是程序员，说真的，看到这些我心情挺复杂的。

一方面觉得，哇，这玩意太牛逼了，生产力要爆炸了。

另一方面又觉得，我靠，我是不是要失业了？

但后来我想通了。

我觉得这不是「人 vs AI」的问题，而是「会用 AI 的人 vs 不会用 AI 的人」的问题。

就像当年 Excel 出来的时候，会计也担心失业。结果呢？会用 Excel 的会计工资更高了，不会用的被淘汰了。

现在也是一样。

会用 Claude Code 这类工具的程序员，效率会是以前的好几倍。不会用的，就会被慢慢淘汰。

这不是危言耸听，这是正在发生的事情。

## 一些实操建议

既然聊到这了，我就给做技术的朋友一些实操建议。

说实话我也不确定这些对不对，我自己也还在摸索，但先分享出来，大家一起探讨。

**第一，现在就开始用 Claude Code。**

别等到「完美时机」，没有那个时机。现在就开始，哪怕只是用它来写一些简单的脚本。先把手感练起来。

一开始可能会有点笨拙，花的时间比手动做还长，这是正常的。我刚开始用的时候，经常觉得它写的东西还不如我自己写。但是坚持用下去，你会慢慢摸到门道。

**第二，改变你的工作习惯。**

遇到问题，先问 Claude，而不是先自己闷头想。让它帮你分析代码、找 bug、做测试。把那些机械性的工作交给它，你专注于真正需要人判断的部分。

这个转变需要时间，不可能一夜之间就适应。我自己也是用了好几个月才慢慢习惯。

**第三，学会「智能体思维」。**

不要把 Claude Code 当成一个工具，把它当成一个团队。学会怎么给它分配任务，怎么让它协调多个子代理，怎么验收它的成果。这是一种新的能力。

这个能力说实话还挺难的，我到现在也还在学习怎么写好 prompt，怎么设计工作流。但这是值得投入的方向。

**第四，关注验证和安全。**

以后代码写得快了，但是怎么保证写得对？怎么保证安全？这会变成核心竞争力。多花时间在测试、审查、安全这些方面。

这也意味着你需要学习新的技能，比如怎么写测试用例，怎么做安全审计。学习曲线会比你想象的陡，但这是必须跨过去的坎。

## 最后

回到最开始的那个问题，Claude Code 更新了两个炸裂功能，到底炸在哪？

我觉得炸在它不是在优化一个工具，而是在重新定义一种工作方式。

以前是人驱动代码，以后是人驱动智能体，智能体驱动代码。

这个变化的深度，可能比我们想象的要大得多。
