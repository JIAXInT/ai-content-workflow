# AI 内容创作工作流

这是一个完整的 AI 内容账号每日创作工作流，覆盖公众号、小红书、抖音三端内容生产。

## 工作流程

### 第一步：获取 AI 热点

当用户说「今日热点」「AI 日报」「看看今天有什么」时：

1. 使用 `aihot` 技能获取最新 AI 热点精选
2. 按以下分类展示：
   - 🤖 模型发布
   - 🚀 产品发布
   - 📊 行业动态
   - 📄 论文研究
   - 💡 技巧与观点
3. 每条热点包含：标题、摘要、来源
4. 等待用户确认要写的选题

### 第二步：确认选题

用户从热点列表中选择 1-3 个感兴趣的选题，支持以下方式：

- 直接说编号：「写第 3 条」
- 说方向：「写那个模型发布的」
- 组合多条：「把 1 和 5 合在一起写」
- 自定义：「我想写关于 XX 的」

### 第三步：获取原文素材（自动化）

用户确认选题后，**自动获取原文素材**作为文章的关键证据。这是增强文章可信度和「活人感」的关键步骤。

#### 自动化流程

1. **提取原文链接**：从选题中自动提取原始 URL（通常是推文、博客、GitHub 等）

2. **自动截取原文**：运行截图脚本获取原文内容
   ```bash
   # 基本用法：截取选题的原文链接
   python scripts/screenshot_webpage.py "https://twitter.com/user/status/123456"

   # 截取多个链接（如果选题包含多个来源）
   python scripts/screenshot_webpage.py "url1" "url2" "url3"

   # 指定输出目录（按文章名）
   python scripts/screenshot_webpage.py "url" -o images/YYYY-MM-DD_article-name/
   ```

3. **浏览器截图工具**（推荐用于 X 平台等有反爬虫机制的网站）：
   ```bash
   # 打开浏览器手动操作后截图（交互式）
   python scripts/browser_screenshot.py "https://x.com/user/status/123456"

   # 等待 10 秒后自动截图
   python scripts/browser_screenshot.py "https://x.com/user/status/123456" --wait 10

   # 指定输出目录
   python scripts/browser_screenshot.py "url" -o images/my-article/
   ```

4. **支持的平台及截图策略**：

   | 平台 | 截图目标 | 说明 |
   |------|----------|------|
   | Twitter/X | 推文卡片 | 使用浏览器截图工具，手动操作后截图 |
   | 微博 | 微博内容 | 截取微博文本和配图 |
   | 知乎 | 回答/文章 | 截取富文本内容 |
   | GitHub | README/Issue | 截取代码和讨论 |
   | 通用网页 | 文章主体 | 智能识别内容区域 |

4. **素材整理与命名**：
   - 输出位置：`images/YYYY-MM-DD_article-name/`
   - 文件命名：`screenshot_{platform}_{date}_{id}.png`
   - 分辨率：2x 高清截图

#### 素材用途

在文章中合理使用截图素材：

- 📸 **推文截图**：作为「原始讨论」素材，展示真实社交讨论
- 📊 **数据截图**：作为「数据支撑」素材，增强可信度
- 💬 **评论截图**：作为「社区讨论」素材，体现多元观点
- 🔍 **代码截图**：作为「技术细节」素材，展示实现细节

#### 在文章中引用

在文章中使用图片语法引用截图，增强可信度和「活人感」：

```markdown
![推文截图](../images/YYYY-MM-DD_article-name/screenshot_twitter_20260603_123456.png)
```

**引用建议**：
- 在提到原始讨论时引用推文截图
- 在展示数据时引用数据截图
- 在分析社区反应时引用评论截图
- 每篇文章至少引用 2-3 张截图

### 第四步：生成公众号文章

用户确认选题后，使用 `khazix-writer` 技能生成公众号长文：

1. **风格定位**：以「AI创享派」风格写作
   - 深度解读，不只是新闻搬运
   - 有观点、有态度、有洞察
   - 通俗易懂，接地气

2. **文章规格**：
   - 字数：4000-8000 字
   - 结构：引言 → 核心内容 → 深度分析 → 总结展望
   - 配图建议：3-5 处
   - **必须使用截图素材**：在文章中引用第三步获取的原文截图，增强可信度和「活人感」

3. **四层自检体系**：
   - **L1 硬性规则**：字数、格式、必含元素
   - **L2 风格一致性**：语言风格、人称、语气
   - **L3 内容质量**：信息密度、逻辑连贯、价值输出
   - **L4 活人感**：口语化、互动感、真实感、**使用真实截图素材**

4. **输出文件**：
   - 文章文件：`{date}_{title}.md`（Markdown 格式）
   - 封面图：`cover.html` + `cover-square.html`
   - 质检报告：包含在文章末尾或单独文件

#### 自动生成封面图

在生成文章的同时，**自动生成公众号封面图**：

1. **封面规格**：
   - 公众号封面：900×383 像素（横版）
   - 朋友圈封面：383×383 像素（正方形）

2. **封面内容**：
   - 品牌标识：「AI创享派」+ 蓝色图标
   - 分类标签：AI 热点
   - 主标题：文章核心标题（精简版，15字以内）
   - 副标题：关键数据或亮点
   - 日期：发布日期
   - 底部装饰：蓝橙渐变条

3. **设计风格**：
   - 配色：莫兰迪色系（雾霾蓝 #6B8FAD + 奶茶棕 #C4A882）
   - 背景：米白 #F5F0EB + 几何装饰
   - 字体：Noto Sans SC + Inter
   - 风格：清爽科技、高级感

4. **生成流程**：
   - 使用 `frontend-design` skill 生成封面 HTML
   - 根据文章标题自动填充内容
   - 保存为 `cover.html` 和 `cover-square.html`
   - 可通过浏览器打开预览或截图

## 注意事项

1. **热点时效性**：优先选择 24 小时内的热点
2. **选题建议**：优先选择有深度、有争议性、有讨论价值的话题
3. **标题党适度**：吸引眼球但不低俗
4. **原创观点**：必须有自己的分析和见解，不能只是搬运
5. **数据支撑**：尽量引用具体数据、案例
6. **互动设计**：文末设置互动话题，引导评论

## 常见问题与最佳实践

### 复盘总结（2026-06-03）

#### 问题 1：作者名称统一
- **问题**：文章中出现"数字生命卡兹克"，需要统一为"AI创享派"
- **解决方案**：全局替换所有文章和配置文件中的作者名称
- **检查清单**：
  - [ ] 文章 frontmatter 中的 `author` 字段
  - [ ] 文章末尾的署名
  - [ ] SKILL.md 中的风格定位
  - [ ] CLAUDE.md 中的工作流说明

#### 问题 2：插图来源
- **问题**：原来使用 AI 生成的插图，现在改为使用原文链接的截图
- **解决方案**：
  1. 从文章中自动提取原文链接（Twitter/X、GitHub、知乎等）
  2. 使用 `screenshot_webpage.py` 截取原文内容
  3. 将截图作为文章插图
- **关键代码**：
  ```python
  # 从文章中提取原文链接
  urls = extract_urls_from_article(article_file)
  
  # 使用 --type viewport 截取视口（包含标题和正文开头）
  cmd = f'python scripts/screenshot_webpage.py "{url}" -o "{output_dir}" --type viewport'
  ```

#### 问题 3：截图参数选择
- **问题**：`--clip top` 只截取了导航栏，没有截取到文章正文
- **解决方案**：使用 `--type viewport` 截取整个视口（1280×900）
- **参数对比**：
  | 参数 | 效果 | 适用场景 |
  |------|------|----------|
  | `--clip top` | 只截取视口上半部分（导航栏） | ❌ 不推荐 |
  | `--clip header` | 截取视口 30% | ❌ 不推荐 |
  | `--type viewport` | 截取整个视口 | ✅ 推荐 |
  | `--type full` | 截取整个页面（包括滚动区域） | 页面内容较短时 |

#### 问题 4：截图插入位置
- **问题**：截图全部放在文章末尾，不够自然
- **解决方案**：按小标题分段插入截图
- **实现逻辑**：
  1. 将文章按小标题分成多个部分
  2. 交替追加内容和插入截图
  3. 每个截图插入到对应内容之后
- **关键代码**：
  ```python
  # 将文章内容分成多个部分
  content_parts = split_content_by_sections(body_content_clean, num_images)
  
  # 交替追加内容和插图
  for i, part in enumerate(content_parts):
      # 追加内容
      append_doc_content(doc_url, part)
      # 插入插图（如果有）
      if i < num_images:
          insert_image(doc_url, article_images[i]["path"])
  ```

#### 问题 5：封面图生成
- **问题**：使用 `--no-cover` 参数导致封面图没有生成
- **解决方案**：默认生成封面图，只在用户明确要求时才使用 `--no-cover`
- **正确用法**：
  ```bash
  # 生成封面图（默认）
  python scripts/save_to_feishu.py articles/YYYY-MM-DD_标题.md
  
  # 不生成封面图（用户明确要求时）
  python scripts/save_to_feishu.py articles/YYYY-MM-DD_标题.md --no-cover
  ```

```bash
python scripts/screenshot_webpage.py "url" -o "output_dir" --type full
```
